## 2. 已实现的安全能力

### 2.1 认证与会话

- 密码哈希：`pwdlib[argon2]`
- 会话：JWT + HttpOnly Cookie，`SameSite=Lax`，生产环境 `Secure`
- 登出：token `jti` 加入黑名单（Redis / 进程内）
- 登录保护：失败计数 + 锁定（Redis / 进程内）
- CSRF：SameSite + Origin/Referer 同源校验（管理端写操作）

### 2.2 接口防护

- 客户端提交：IP 限流 + 手机号限流 + 分布式锁 + 同报告唯一性（手机号/邮箱/IP）
- 诊断上报：限流 + 长度截断
- 输入校验：单位/职务 ≤512、姓名 ≤32、手机号正则、邮箱仅 ASCII 域名、邮箱格式
- 报告 id：32 位 uuid4 hex，不可枚举
- 报告时间段：未开始/已结束不可提交（前端提示页 + 后端拦截）

### 2.3 数据与日志

- `config.yaml` 保存全部密钥，已 gitignore
- 诊断日志自动脱敏；生产默认关闭
- 管理操作审计：审核、发邮件、报告增删改写入 `audit_logs`
- SQLite：WAL、外键约束、busy_timeout、短事务

### 2.4 并发处理（Redis）

| 能力 | Redis 键 | 说明 |
| --- | --- | --- |
| 提交限流（IP） | `reportc:rl:submit:ip:*` | INCR + EXPIRE，60 秒窗口 |
| 提交限流（手机号） | `reportc:rl:submit:phone:*` | 3600 秒窗口 |
| 重复提交锁 | `reportc:submit:lock:*` | SET NX EX 10 秒 |
| 登录失败锁定 | `reportc:login:fail/lock:*` | 5 次 / 15 分钟 |
| JWT 黑名单 | `reportc:jwt:revoked:*` | TTL = token 剩余有效期 |
| 任务队列 | `reportc:jobs` | LPUSH + BRPOP，worker 消费 |

## 3. 残留风险与建议

| 项 | 建议 |
| --- | --- |
| 暴力破解 / 扫描 | 加 WAF 或 fail2ban；Nginx 层限制 `/api/admin/auth/login` 频率 |
| 人机校验 | 如出现批量恶意提交，可在客户端提交前加图形验证码 |
| 依赖漏洞 | 定期执行 `pip-audit`、`npm audit`，及时升级 |
| 数据备份 | SQLite 每日 `sqlite3 app.db ".backup ..."`，保留 7~30 天，异地保存 |
| 数据量增长 | 若未来并发写入明显增加，建议迁移 PostgreSQL（SQLAlchemy + Alembic 已兼容） |
| 隐私合规 | 收集个人信息需告知同意；建议在客户端增加隐私说明与保留期限 |

## 5. 生产部署（gunicorn + nginx + redis）

- 一键脚本：项目根目录 `deploy.sh`
  - `gunicorn app.main:app --worker-class uvicorn.workers.UvicornWorker --workers N --bind 127.0.0.1:8600`
  - systemd：`reportc-api.service`（API）、`reportc-worker.service`（Redis 任务 worker）
  - Nginx：静态资源 + `/api/` 反代，**透传 `X-Forwarded-For`**（限流按真实 IP 生效）
- SQLite 与多 worker：默认 `--workers 2`；SQLite 单写，worker 数不建议超过 4
- 同报告唯一性规则可在 `security` 中分别开关：

```yaml
security:
  unique_phone_per_report: true
  unique_email_per_report: true
  unique_ip_per_report: true    # 注意 NAT：同一出口 IP 的多人会被判为重复
```

> ⚠️ **IP 唯一性风险**：企业/校园/运营商 NAT 出口可能大量用户共用同一公网 IP，开启后同一报告下这些用户只能提交一次。若填报人群集中办公网，建议关闭该项或改为"IP 限流"而非"IP 唯一性"。
