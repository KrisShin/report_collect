## 1. 目标与范围

### 1.1 一句话目标

用户在微信中打开客户端链接，完成微信身份授权后填写手机号等信息并提交；提交成功后自动通过飞书机器人提醒管理员。管理员在管理端登录后查看、筛选、排序、导出、复制邮箱，并通过腾讯企业邮箱批量发送带附件的邮件。

### 1.2 两个入口

| 入口 | 使用者 | 访问方式 | 浏览器限制 |
| --- | --- | --- | --- |
| 客户端 `/m` | 报告填写人 | 微信内打开链接 | 仅允许微信内置浏览器 |
| 管理端 `/admin` | 管理员 | 任意现代浏览器，优先移动端 | 不限制，但需账号密码登录 |

### 1.3 本期范围

- 客户端表单：单位、职务、姓名、电话、邮箱。
- 微信身份获取（openid）；手机号手动填写并校验格式。
- 表单校验、提交、提交成功页。
- 提交后飞书群机器人提醒。
- 管理端登录、表格、字段过滤、全字段排序、多选/全选。
- 一键导出（Excel 附件）、一键发送邮件、一键复制选中邮箱（`;` 分隔）。
- 邮件模板 + 附件模板。
- 移动端适配。

### 1.4 暂不包含（可后续迭代）

- 多角色/多租户权限体系。
- 用户自助查询/修改/撤回提交。
- 短信通道（除非手机号方案选择短信验证码）。
- 数据大屏、统计报表。
- 复杂审批流（多级审核、会签）。

## 2. 关键技术结论

### 2.1 手机号方案（已决策：手动填写）

> **已决策（D1）：本次采用方案 B —— 手机号由用户手动填写，仅做格式校验。**
>
> 以下背景保留作为技术记录：这是本方案原先最关键的可行性问题。

- **微信公众号网页授权（OAuth2）** 只能拿到 `openid`、`unionid`、昵称、头像、地区等，**不包含手机号**。
- **微信“手机号快速验证/一键获取手机号”** 是**微信小程序**能力（`<button open-type="getPhoneNumber">` + 后端 `phonenumber.getPhoneNumber`），**不是公众号 H5 能力**。
- 因此“React 19 网页 + 微信浏览器内自动获取手机号”无法用微信官方接口直接实现。

可选方案：

| 方案 | 做法 | 优点 | 缺点 | 推荐度 |
| --- | --- | --- | --- | --- |
| A. 小程序壳 + H5 | 用微信小程序（原生/Taro/uni-app）承载入口，在小程序页面调用 `getPhoneNumber` 拿到手机号，再跳转/内嵌 H5 表单，手机号透传 | 微信官方能力，体验最好，可真正“一键授权” | 需要小程序主体与审核；前端多一个小程序壳（可不用 React 写壳） | ★★★★★（若必须自动获取） |
| B. 公众号 H5 + 手动填写 | 网页授权拿 openid；手机号字段手动填写并做格式校验；可选短信验证码 | 完全符合 React 19 技术栈，实现最快 | 无法自动获取手机号 | ★★★★（本次 React 方案默认） |
| C. 运营商一键登录 | 集成运营商号码认证 H5 SDK | 可自动获取本机号 | 收费；依赖蜂窝网络，WiFi 下常失败；微信内兼容性有风险 | ★★ |
| D. 微信支付/会员能力 | 通过支付等场景间接获取 | — | 不满足“提交表单”场景，限制多 | ★ |

**已决策**：本次按 **方案 B** 落地 React 19 H5，手机号手动填写；服务层仍保留 Provider 接口，未来需要时可替换为小程序取号或运营商取号。

### 2.2 其他关键结论

1. **“仅限微信浏览器”只是体验层限制**：前端检测 UA 是否包含 `MicroMessenger`，后端记录 UA/IP。它不能当作安全边界（UA 可伪造）。
2. **微信网页授权需要**：已认证服务号、`AppID/AppSecret`、公网 HTTPS 域名，并在公众号后台配置“网页授权域名”（需 ICP 备案域名，且要能放置校验文件）。
3. **飞书 `tenant_access_token` 有效期 7200 秒**：后端必须缓存复用（建议提前 300 秒过期），不要每次发送都重新获取。
4. **飞书机器人需要**：应用开通 `im:message` / `im:message:send_as_bot` 权限，且机器人已被拉入目标群；否则会返回权限错误。
5. **腾讯企业邮箱 SMTP**：`smtp.exmail.qq.com`，SSL 端口 `465`（或 STARTTLS `587`），需在邮箱后台开启 SMTP 并使用客户端专用密码（用户提供的 key 应作为授权码使用）。
6. **邮件附件**：由后端用 `openpyxl` 动态生成 `.xlsx` 后作为附件发送，不落盘或落临时目录后立即清理。
7. **密钥安全**：本次对话中提供的飞书 Secret、邮箱 key 属于敏感信息，正式开发时必须写入 `.env`（加入 `.gitignore`）或密钥管理服务，并建议尽快轮换。

## 8. 页面与交互

### 8.1 客户端 `/m`

1. 进入页面 → 检测 `MicroMessenger`；非微信环境显示“请在微信中打开”提示页。
2. 触发微信网页授权 → 获取 openid（授权失败则给出重试入口，且不允许提交）。
3. 手机号：
   - 方案 A：小程序 `getPhoneNumber` 一键授权；
   - 方案 B：尝试获取，失败/未授权则空，允许手动填写；为空不允许提交。
4. 表单字段：单位、职务、姓名、电话、邮箱。
5. 提交后跳转/展示成功页：“提交成功，等待管理员审核后发送到邮箱”。
6. 移动端：大输入框、数字键盘（电话）、邮箱键盘、底部固定提交按钮、提交中禁用防重复。

### 8.2 管理端 `/admin`

1. 登录页（账号、密码、错误提示、登录限流）。
2. 首页即表格列表：移动端卡片式/横向滚动表格。
3. 顶部过滤器：任意字段输入过滤 + 状态过滤 + 时间范围。
4. 表头排序：所有字段可排序。
5. 多选/全选：跨当前页全选，显示已选数量。
6. 操作按钮：一键导出、一键发送邮件、一键复制选中邮箱。
7. 行详情/审核：查看详情，审核通过/驳回，发送状态与失败原因。
8. 移动端：筛选收进抽屉，操作按钮收进底部操作栏/ActionSheet。

### 8.3 需要明确的交互规则

- 未勾选任何行时，导出/发邮件作用于**当前筛选结果**还是禁用？（建议：默认禁用，提供“导出全部筛选结果”二级入口）
- 复制邮箱：是否去重、是否排序？（建议去重 + 去空白 + `;` 拼接）
- 全选：仅当前页还是全部筛选结果？（建议默认当前页，提供“选择全部 N 条”）

## 9. 关键流程

### 9.1 提交流程

```text
微信内打开链接
  → 校验 UA（非微信 → 提示页）
  → 微信网页授权 → 后端换 openid（+ unionid）
  → 获取手机号（方案 A/B）
  → 填写表单（前端 Zod 校验 + 后端 Pydantic 校验）
  → POST 提交
  → 写 submissions(status=pending)
  → 异步/同步发送飞书提醒
  → 返回成功页
```

### 9.2 飞书提醒流程

```text
提交成功
  → 取缓存 tenant_access_token（无则 POST /auth/v3/tenant_access_token/internal）
  → POST /open-apis/im/v1/messages?receive_id_type=chat_id
     body: receive_id=群 chat_id, msg_type=text/interactive,
           content=JSON 字符串
  → code==0：标记 feishu_status=sent
  → 否则：记录 code/msg 到 feishu_error，标记 failed，提供管理员手动重发
```

建议消息内容：

```text
【新的报告提交】需要审核
```

## 17. SQLite 专项说明（已确认 D2）

SQLite 用于万级数据量完全可行，但要注意以下工程细节：

| 项 | 建议 |
| --- | --- |
| 驱动 | SQLAlchemy async + `aiosqlite`；连接串 `sqlite+aiosqlite:///./data/app.db` |
| 并发 | SQLite 单写多读；启用 `PRAGMA journal_mode=WAL`、`PRAGMA busy_timeout=5000`、`PRAGMA foreign_keys=ON` |
| 事务 | 写操作保持短事务，避免长事务阻塞 |
| 备份 | 每日使用 `sqlite3 app.db ".backup backup_YYYYMMDD.db"`，保留最近 N 份；不要只复制 WAL 模式下的主文件 |
| 迁移 | 使用 Alembic；类型选择保持跨库兼容，便于未来平滑迁到 PostgreSQL |
| 扩展 | 不适用多实例横向扩展；单机单进程足够 |
| 附件/导出 | 用临时目录生成后即删，不把大文件写入库 |
